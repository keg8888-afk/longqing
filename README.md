# Каталог Longqing — ООО «ВИРА» (версия 4, GitHub Pages + longqing.ru)

Каталог продукции Shandong Longqing Heavy Industry: 7 групп техники, 37 моделей,
многостраничная структура (главная + 7 страниц категорий), технические характеристики,
FAQ, контакты. Оптимизирован для поисковых систем и генеративных движков (Яндекс Нейро,
ChatGPT, Perplexity, Gemini).

## Что нового в версии 4 (GEO-оптимизация)

- **7 страниц категорий** с собственными URL (цитируемые источники для ИИ-поиска):
  `/kolenchatye-podemniki/`, `/nozhnichnye-podemniki/`, `/gusenichnye-podemniki/`,
  `/machtovye-podemniki/`, `/trekhkolesnye-podemniki/`, `/mini-pogruzchiki/`,
  `/teleskopicheskie-podemniki/`. Каждая страница: уникальный текст, модельный ряд,
  особенности, **видимые таблицы характеристик** (раньше — только в модальных окнах),
  мини-FAQ, хлебные крошки, JSON-LD (BreadcrumbList + ItemList/Product + FAQPage).
- **H1 главной страницы переведён на русский**: «Подъёмные платформы и мини-погрузчики
  Longqing — официальный каталог» (было латиницей — название завода).
- **llms.txt и llms-full.txt** (формат llmstxt.org) — файлы-справочники для LLM:
  краткая версия с ключевыми фактами и ссылками + полный текст каталога и FAQ.
- **robots.txt**: явно разрешены AI-краулеры — GPTBot, OAI-SearchBot, ChatGPT-User,
  ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User,
  Google-Extended, Applebot-Extended, Bytespider, CCBot, Amazonbot.
- **sitemap.xml**: 8 URL (главная + 7 категорий) с изображениями.
- **JSON-LD на главной**: ItemList товаров теперь ссылается на страницы категорий
  (раньше — на якоря #sec01…#sec07, у которых нет отдельных URL).
- **Навигация**: в каждой секции каталога — ссылка на страницу категории; в футере —
  ссылки на категории (в липкой навигации якоря сохранены).
- Исправлена статистика: 37 моделей в каталоге (было 35).
- Цены не публикуются (по решению владельца) — Product без offers, цена по запросу.

## Публикация на GitHub Pages (пошагово)

1. Создайте репозиторий на GitHub (например, `longqing-site`) и загрузите **все файлы
   из этого архива в корень репозитория** — включая папки категорий, `llms.txt`,
   `llms-full.txt` (index.html, папки `*/`, images/, CNAME, robots.txt, sitemap.xml,
   404.html, .nojekyll, googlec0c6de94504d81af.html).
2. В репозитории откройте **Settings → Pages**.
3. В поле **Build and deployment → Source** выберите `Deploy from a branch`,
   ветка `main`, папка `/ (root)` → **Save**.
4. В **Settings → Pages → Custom domain** укажите `longqing.ru` → **Save**.
   GitHub проверит DNS и выдаст сертификат Let's Encrypt.
5. После успешной проверки (обычно 10–60 минут, максимум 24 ч) включите
   **Enforce HTTPS** галочкой в том же разделе.

## Настройка DNS у регистратора reg.ru (безошибочный вариант)

Зайдите в личный кабинет reg.ru → Мои домены → **longqing.ru → DNS-серверы и управление DNS (зона)**.
Удалите стандартные/парковые записи, если есть, и создайте:

**1. A-записи для основного домена (@ / longqing.ru)** — 4 записи, все с TTL 3600:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |

**2. CNAME для поддомена www:**

| Тип | Имя | Значение |
|-----|-----|----------|
| CNAME | www | longqing-site.github.io. (вместо longqing-site подставьте имя вашего репозитория или аккаунта — см. примечание) |

> Примечание: значением CNAME должен быть адрес вашего GitHub Pages сайта:
> `<username>.github.io.` (для репозитория `username.github.io`) или
> `<username>.github.io.` с включённым кастомным доменом в настройках Pages для проектного
> репозитория. Точка в конце — необязательна: reg.ru добавит её сам.

**3. Что проверить, чтобы DNS-ошибок не было:**

- В reg.ru **не должно остаться** других A-записей для `@` и записей для `www`
  (парковка reg.ru, редакторы, почтовые переадресации) — конфликтующие записи
  вызывают ошибку «DNS check unsuccessful» в GitHub.
- Если к домену подключены reg.ru-неймсерверы (ns1.reg.ru / ns2.reg.ru) — настраивайте
  записи именно через панель «DNS-серверы и управление DNS».
- Изменения DNS распространяются от 15 минут до 24 часов. Пока GitHub не увидит
  корректные A-записи, пункт Custom domain будет показывать ошибку проверки —
  это нормально, повторите проверку позже.
- После включения Enforce HTTPS сайт открывается по https://longqing.ru,
  а www.longqing.ru автоматически редиректится на основной домен.

## Индексация и AI-поиск (чек-лист после публикации)

1. **Яндекс Вебмастер** (meta-верификация уже в коде): добавить сайт https://longqing.ru/,
   отправить sitemap `https://longqing.ru/sitemap.xml`, запросить переобход главной.
2. **Google Search Console** (meta + HTML-файл уже в коде): добавить ресурс,
   подтвердить, отправить sitemap.
3. Проверить доступность для ИИ: `https://longqing.ru/llms.txt`,
   `https://longqing.ru/llms-full.txt`, `https://longqing.ru/robots.txt`.
4. Канонические адреса: `https://longqing.ru/` и `https://longqing.ru/<категория>/`.
5. Индексацию проверить запросами `site:longqing.ru` (Яндекс/Google).
6. **Внешние сигналы** (вне сайта): создать карточку в Яндекс.Бизнес (Справочник),
   зарегистрировать профиль поставщика в 2ГИС/Pulscen — генеративные движки
   используют их как источники для ответов о поставщиках.
